## 2. Figures — all 11, with what each one proves

All at `docs/figures/`. Figures 08–11 are regenerated by
`scripts/make_report_figures.py`, which **calls the shipped modules** rather than
drawing mock-ups — the numbers in them are return values, not literals.

### 2.1 Corpus and data honesty

**`01_corpus_funnel.png`** — AndroZoo selection funnel.
27,606,781 → 8,127,036 → 5,174,287 → 10,599. **70.6% of rows dropped for an
implausible `dex_date`.** This is the figure that justifies the date-plausibility
window: AndroZoo carries a ZIP-epoch fallback (1980/81) and impossible futures
(2039+), and unfiltered they all land on one side of a time split.

> Caption for the report: *Without the plausibility window the time split would be
> mostly noise — v1's 6,000-row list had 1,235 rows (20.6%) dated 1980/81, all in
> train, and 23 rows dated 2039–2107, all in test.*

**`02_corpus_bands.png`** — composition by time band.
Three bands hit the 1,500/1,500 target. The 2024–2026 malware band yielded
**99 of 1,500**. This is a negative result and it is the *reason* the MalwareBazaar
backfill exists. Show it — it is the most defensible slide in the deck.

**`corpus_composition.png`** — label/split breakdown of what was actually extracted.

### 2.2 Model

**`precision_recall.png`** — two curves on one axis: random split (PR-AUC 0.993)
vs time split (0.954). The gap **is the finding**, not an embarrassment: it is the
quantitative argument for why the behavioural and GenAI layers exist.

**`reliability.png`** — predicted vs observed frequency, raw vs calibrated.
⚠️ **Regenerate before submitting** — the legend says "isotonic" but
`models/metrics.json` records `"calibration_method": "sigmoid"` (Platt, chosen for
the 48-sample calibration split). The curve is real; the label is stale.

**`feature_importance.png`** — top 18 features by gain. The model leans on
`perm:READ_PHONE_STATE`, `perm:SEND_SMS`, `combo:SILENT_SMS_FRAUD`,
`reach:device_id`, `combo:OTP_THEFT_SURFACE`. Note that **reachability and
permission-combination features earn their place** — these are not bag-of-permissions.

### 2.3 Pipeline

**`04_stage_timing.png`** — M1 1.32 s · M2 2.60 s · M5 <0.01 s · M4 2.33 s ·
M6 <0.01 s = **6.3 s** on a 50.5 MB real malware sample. The scorer being <10 ms is
a design consequence: it is pure, does no I/O and calls no LLM.

**`03_score_factors.png`** — score composition for
`com.brightoilonline.c2b_phone`, S = 46 (MEDIUM).
`S = 0.25R + 0.50F_AI + 0.15G + 0.10D`, and **three of four terms are zero, each
for a stated reason** (no intel hit, no YARA ruleset, nothing detonated). This is
the anti-hand-waving figure: the score is arithmetic you can audit.

**`07_terminal_run.png`** — a real terminal capture of `drishti analyse` on the
canary, then `drishti ledger verify`, then a tamper, then re-verify:

```

reason: node_hash does not match the node's content (tampered)
```

### 2.4 Evidence integrity

**`05_ledger_integrity.png`** — node-type histogram (26 nodes: 8 `score_factor`,
4 `manifest_entry`, 4 `string_const`, 2 `sink_hit`, 2 `api_trace`, 1 each of
`ai_claim`, `certificate`, `call_path`, `file_meta`, `threat_intel`,
`ml_prediction`, `technique_map`) beside the verification result. **One byte
changed → `first_bad_seq = 7`.** Append-only is enforced by SQL triggers, not by
Python politeness; each node is sha256-chained and Ed25519-signed.

### 2.5 GenAI

**`06_genai_determinism.png`** — five identical runs on the same APK produce
B = 0.925, **0.700**, 0.925, 0.925, 0.925. Run 2 asserted one behaviour instead of
two. This is a *self-reported limitation* and it is worth more than a clean chart:
it is why the LLM emits enumerated booleans and **Python computes B from a weight
table**, and it quantifies exactly how much residual non-determinism survives that
design.

### 2.6 M3 dynamic layer — generated live by `make_report_figures.py`

**`08_rule11_aggregation.png`** — the 1,925-event case.
One `Cipher.doFinal` event and 1,925 of them both produce **1 ledger node** and
**b_dynamic = 0.4000, identical**. A realistic 1,929-event / 5-group trace gives
b_dynamic = 0.9887. Aggregation is a formatting change that provably cannot move a
score.

**`09_containment_probe.png`** — the trustworthiness gate, run three ways:

| Probe | Verdict |
|---|---|
| v1's probe (`nc -z`) | **REJECTED** — positive control unreachable |
| always-reachable probe | **REJECTED** — negative control reachable |
| shipped probe | **TRUSTED** — distinguishes open from closed |

v1 shipped row 1. Android's toybox `nc` has no `-z` flag, so it exited 1 with
`Unknown option 'z'` for every host: **every containment check passed regardless of
the real network state, and the signed manifest attested containment that had never
been tested.**

**`10_evasion_detection.png`** — three trace shapes through the real detector:

| Trace | Verdict | Morphs |
|---|---|---|
| 2 probes, no other behaviour | **STALLED** | `install_packages`, `sms_history` |
| no observations at all | **STALLED** — "inconclusive, never benign" | — |
| 1 probe + 20 events of real action | **RAN** | — |

**`11_detection_surface.png`** — 29 sinks / 10 categories, and MITRE coverage:
21 techniques in the KB, 18 reachable from at least one layer. The technique mapper
is **deterministic — the LLM is not in that path**, so it cannot hallucinate a
plausible-looking technique id that no evidence supports.

## 3. The one sample walked end-to-end

`com.brightoilonline.c2b_phone` — 50.5 MB real malware sample from the corpus.

| Stage | Output |
|---|---|
| M1 ingest | sha256 recorded, zipped `infected` at rest, 1.32 s |
| M2 static | permissions, 29-sink scan, backward BFS from sinks with entrypoint attribution, 2.60 s |
| M5 features | 340-dim vector via the **same** `features.extract` training uses, <0.01 s |
| M4 GenAI | 1 call, behaviour booleans → `B = 0.925` via the weight table, 2.33 s |
| M6 score | `F_AI` = noisy-OR(P_cal, B) = 0.925 → **S = 46, MEDIUM**, <0.01 s |
| Ledger | 26 nodes, chain verified, one tamper → `first_bad_seq = 7` |

Canary walk-through (`in.drishti.canary`, figure 07): sinks `pkg_query` +
`reflection`, call path `pkg_query ← onCreate` at depth 2, 74 features, B = 0.97,
**S = 48 MEDIUM, C = 0.021, γ = 0.7**, 29 ledger nodes, 5.04 s wall.

**The confidence demonstration is worth a slide of its own.** C moved
**0.021 → 0.637** once `P_cal` (0.79) and `B` (0.70) *agreed*. Confidence is
γ = 0.4·static + 0.3·(dynamic AND detonated) + 0.2·ml + 0.1·intel — so a system
with nothing detonated is structurally incapable of reporting high confidence, and
that is the intended behaviour.

## 5. Data-honesty findings worth reporting as findings

These are negative results. Reporting them is the strongest thing in the pack.

1. **70.6% of AndroZoo rows have an implausible `dex_date`.** Unfiltered, the time
   split is meaningless.
2. **Recent Android malware is the binding supply constraint.** AndroZoo's full
   index yielded 99 samples for 2024–2026 against a 1,500 target; a 4 MB-capped
   list yielded 5. MalwareBazaar backfilled 571 (Arsink 71, SpyNote 56, Coper 48,
   MoqHao 6) — labelled by a *different* pipeline than AndroZoo's `vt_detection`,
   which must be disclosed wherever composition is reported.
3. **Reputation inputs must not be label-derived.** AndroZoo labels come from
   `vt_detection`; feeding a VT-derived signal into `R` makes composite-score
   metrics circular. `reputation.py` refuses a label-derived feed by default.
4. **GenAI is not deterministic** (figure 06) — quantified at 1 divergent run in 5.
5. **A sample with no observations is `inconclusive`, never benign.**
   Environment-aware stalling is indistinguishable from a clean app.
6. **More workers made corpus download slower** — 8 workers = 96 samples/hr,
   24 workers = 37/hr. AndroZoo rate-limits per key.

## 8. Safety posture (for the report's methodology section)

- No sample is ever opened by an installer, emulator, or `subprocess` on a
  developer machine. Static parsing with androguard is laptop-safe; `adb install`
  is not, and is structurally prevented.
- Corpus APKs live in a private, versioned GCS bucket and the VM's ephemeral
  scratch. Never committed, never copied to a laptop, stored zipped with the
  `infected` convention at rest.
- The corpus extractor carries a **dual guard**: an explicit flag *and* a check
  that `/sys/class/dmi/id/product_name` contains "Google". It refuses to run off-VM.
- Detonation containment is a firewall property: default-deny egress, explicit deny
  to `169.254.169.254/32` (metadata), RFC1918, and the internet.
- A containment failure aborts the batch. It never downgrades to a warning.

## 9. Do NOT claim these — nothing has been detonated

State this plainly in the report's Limitations section. It is generated from real
flags (`partial`, `source == replay`, `composite`, `synthetic`, rejected-claim
count), never hardcoded.

- **No APK has been executed.** No emulator has run, no Frida hook has fired
  against a real sample, no probe has touched a real network. `hooks.js` (13 emit
  sites, 11 hooked methods including `Cipher.doFinal`) is syntax-checked and
  statically audited in CI — **never executed**.
- The detonator VM **does not exist**; see `docs/M3_DETONATOR_RUNBOOK.md`.
  Unbuilt: `emulator.py`, `frida_runner.py`, snapshot/crash self-repair,
  mitmproxy/TLS, morph scripts.
- Figures 08–10 demonstrate the **analysis layer** on constructed traces through
  the real code. They are not detonation results and must not be captioned as such.
- Every dynamic number in the paper (§4.3, §6, half of Table 6) currently comes
  from committed fixtures. Label them.
- Model metrics come from **205 train / 144 test / 48 calibration** samples — a
  pilot, not an evaluation. Do not quote PR-AUC without the n.
- v1's dynamic pilot was 9 samples executed, 7 with data. **Never quote 12.**
- Whether observed techniques *distinguish* malware from ordinary apps is
  unmeasured. No benign dynamic baseline exists.
- Replay vs. live is read from the trace (image version, VM instance id, run
  timestamp), never from a config flag. Replaying a real captured trace is
  legitimate **and must be disclosed on screen**.
