# Institutions Indian mobile fraud impersonates, as they appear in UI text.
#
# WHY THIS FILE EXISTS
#
# The Social-Engineering Analyst (PHASE_3 T3.8) answers "who is this aimed at, and who
# is it pretending to be". The second half must not be a model's impression. A brand
# name is a literal string in the app's resource table, so matching it is a lookup and
# the evidence is the string itself — which the profile then cites, and the verifier
# then checks.
#
# FORMAT
#   token | canonical name | sector
#
# `token` is matched case-insensitively as a whole word against UI strings and the app
# label. Tokens are deliberately distinctive: "bank" alone would match every banking
# app in the store, and a lexicon that fires on everything asserts nothing.
#
# STATUS: a detection aid, not a registry, and NOT a claim that the named institution
# has been attacked. A hit means the sample's own strings name that institution — which
# is a fact about the sample, not about the institution. Add freely; a miss weakens one
# signal among several and never produces a verdict on its own.
